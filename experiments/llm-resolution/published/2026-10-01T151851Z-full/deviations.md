# Deviations, 2026-10-01T151851Z-full

How this run differed from the experiment's [README](../../README.md) and from [the article that set the experiment out](../../../../docs/articles/18-a-resolver-that-reads-the-systems-model.md), and what the checks on its files found. Dates are UTC.

- 2026-10-01, before the first run. Until then the `grep` and `read` tools, and the search the `code` tool makes for an element's values, left out every folder named `model`, which hid the adapter's `adapter/model` package, fourteen Go files holding 31 of the 169 tests and 23 of the 69 that carry a key. The tools were changed to leave out `model`, `docs` and `experiments` only at the top of the checkout, as `EXP-SR-18` now says, in [#65](https://github.com/Roarge/sysml-federation/pull/65), which reached `main` through [#67](https://github.com/Roarge/sysml-federation/pull/67). This run used the changed tools.
- 2026-10-01, the code at the run's commit. The report's every-element share counts within all the elements of the systems model, 1,345 besides the recorded requirement, among them the 69 test entries of the verification register that the test task hides. The article counts within the 1,277 elements the test task shows. On the article's example of `SR-22`, this run counts 163 elements within two links and 521 within three, where the article gives 157 and 515. [`outcomes.md`](outcomes.md#near-misses) gives the figures.
- 2026-10-01, the code at the run's commit. The citation check is more lenient than the article describes. A cited file need only exist in the checkout, so a file no tool could have shown passes, and so does a line number past the end of a file. A path that climbs out of the checkout with `..` is looked up outside it. The same element twice in a row passes as a join. An element and a file join when the file is any of the places the `code` tool gives for the element, including those its answer leaves out. A file shown by `grep` or `code` counts as read. [`outcomes.md`](outcomes.md#citation-failures) gives the detail.
- 2026-10-01. The README estimates that a full run takes about two hours on a 12 GB graphics card generating about 22 tokens a second. On this run's NVIDIA RTX A2000 12GB the language model generated a median of 20.47 tokens a second, and the run took 18,495 seconds of wall-clock time, 5 h 08 min 15 s.
- 2026-10-01. The seconds the program records come from the monotonic clock of the machine that ran it, and that clock ran fast. They are the seconds given for each question in `run.jsonl`, and every time figure built from them in the summary line and in `report.md`, such as the report's total of 315 minutes. The questions were asked one at a time, yet their recorded seconds add up to 18,875.7, more than the 18,495 seconds of wall-clock time between the run's start and its end, so the clock ran at least 2 per cent fast. The server's own timings for the same 2,433 replies add up to 18,340.2 seconds. The machine's wall clock agreed with the server's clock and with network time when checked during the run. [`environment.json`](environment.json) takes the run's duration from the wall clock and its throughput from the server's timings.
- 2026-10-01, after the run. `go run . -report` on `run.jsonl`, at the run's commit, gives a report identical byte for byte to `report.md`.
- 2026-10-02. The files were checked for private data before publishing, and none was found. No value was replaced, so `run.jsonl` is the results file byte for byte.
