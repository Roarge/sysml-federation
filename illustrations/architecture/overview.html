Pipeline demo: the architecture in five views

The entity of interest is the demo: the SysML adapter, the example stack behind it and the image they ship in. The pipeline the example models is a system the demo describes, never the demo itself. Each view answers the concerns of named stakeholders and has a text form in the architecture description, which is the record.

V1 Context

the visitor

The demo among the things it touches: a browser with two tabs, the Docker host, the registry the image is pulled from, the maintainer's machine. Nothing leaves the container while it runs.

What is inside, what is outside, what crosses the line?

V2 Composition

the model owner, the document owner, the maintainer, an organisation deciding

Three subgraphs, their schemas, the entity keys they join on, and the merged graph the router serves. Who owns which field, and what the capacity service has to agree with the adapter.

What do the services agree on?

V3 Runtime

the visitor, the model owner, the document owner

What happens on an edit: mutation, version event, fan-out, refetch, rollup on read, render in both apps. The case where nothing moves, a document edit, a reset, and startup.

How does a change in one tab reach the other?

V4 Deployment

the maintainer, an organisation deciding

One container, one process tree, one published port. The image layers, the router copied in and its licence fetched beside it, the environment that keeps it offline, the build and the tag-triggered publish.

What runs where, and how does it get built?

V5 Adapter

the model owner, the maintainer, a contributor

Inside the one reusable component: lexer, parser, AST with source spans, resolver, projection, server. How an edit patches the text, how unsupported syntax is refused, how the example is validated.

How does a model file become a subgraph?
